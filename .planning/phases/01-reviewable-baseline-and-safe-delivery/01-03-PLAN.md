<objective>
Turn one undifferentiated 1036-insertion / 1662-deletion working-tree diff into six commits a
reviewer can read one at a time, without editing a single line of the rewrite.

Purpose: OPS-03. The rewrite is the largest change this project will make and it currently exists
only as dirty working-tree state — unbacked, unreviewable and one careless `git restore` from
gone. Slicing it by concern is what makes the next eleven phases able to `git blame` an answer
out of this file.

Output: six commits on local `main`, a working tree with no output from `git status --porcelain`,
and a proof that the series reproduces the rewrite byte-for-byte.
</objective>

<method>
`git add -p` and `git add -i` are interactive and unavailable to the executing agent, so hunk
staging is not an option. The technique is **snapshot branch plus structural reconstruction**:
park the dirty tree on a throwaway branch so the content is in the object store, return to `main`
(which restores the committed page), then rebuild the file one concern at a time by taking
absolute line ranges out of the frozen snapshot and inserting them into the mutating working file
at structural markers.

Why this beats splitting the unified diff: every intermediate file state is a state you chose and
can inspect, the final state is provably byte-identical, and nothing depends on diff hunk
alignment.

**Verified line boundaries in the rewrite**, read from the working-tree file at planning time.
`.claude/CLAUDE.md` documents these regions as "FR L121-552, EN L553-980, JS L982-1052"; those
numbers are stale by one to two lines. Use these.

**Slice algebra.** Writing `V[a..b]` for lines `a` through `b` of the frozen snapshot, each slice
leaves the working file in exactly this state:

| Slice | Resulting file |
|---|---|
| 1 | `V[1..77] + V[116] + committed[609..1686]` |
| 2 | `V[1..116] + committed[609..1686]` |
| 3 | `V[1..550] + V[1053..1054]` |
| 4 | `V[1..980] + V[1053..1054]` |
| 5 | `V[1..1054]` — byte-identical to the snapshot |
| 6 | `README.md` restored from the snapshot |

Slices 1 through 4 leave a page that renders imperfectly. D-02 permits this explicitly:
readability of the series wins over per-commit renderability, and only the final commit must
leave the page correct. Nothing is pushed in this plan, so no imperfect state ever reaches a
visitor.
</method>
